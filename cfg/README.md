# Certificate
WebRTC doesn't use certificate authorities, you just self generate.  But, your certificate is part of your address information so you want to rotate slowly to invalidate your address infrequently.

# Network Configuration
For a container, this would require --priveledged. The NET_ADMIN capability would let you make the VRF, but the TUN interfaces seem to need priveledged.

## Routing Table: Main
- Tell the system IP/SCTP stack about our network
	- fd00::/8 -> relay-isolation

## Routing Table: VRF relay-isolation
- Disallow IPv4
	- 0.0.0.0/0 -> blackhole
- UDP TURN
	- ::/0 -> turn
- TCP TURN
	- fd01:{SITE_ID}::{STREAM_INDEX}/64 -> turn
- DTLS Contexts
	- fd02:{RANDOM_DTLS_CONTEXT}/16 -> vpn
		- These must be IP6/UDP/DTLS packets
	- fd03:{SITE_ID}::{CONTEXT_INDEX}/64 -> vpn
		- These must be IP6/SCTP packets
- SCTP Associations / Allocated IP addresses
	- fd04:{SITE_ID}::{CONTEXT_INDEX}/96 -> vpn
		- I'm currently using one-to-one SCTP sockets which are split-off and stored on their DTLS context.
- Inter-Site communication
	- fd00::/8 -> site-vlan?

## IP Address assignments
 - fd00:{SITE_ID}::/96 on VRF relay-isolation

## Routing Argument Widths
- SITE_ID: u16 identifying this server
- RANDOM_DTLS_CONTEXT: u96 a random number generated per-connection.
	- Currently generated by the client as the ip portion of a random ip+port socket address.
	- In the future, the goal is to support multiple certiificates via DNS: bas62-x509-sha256-fingerprint.stun.evan-brass.net -> fd02:{SITE_ID}:{CERT_ID}:{RANDOM_DTLS_CONTEXT} for our own certificates (since we don't use ICE) and -> fd04:{SITE_ID}::{ASSOC_ID} for clients who connected to our VPN through DTLS with a peer certificate (they'll have to handle ICE on their own with the limited 16bits of port entropy).
- ASSOC_ID: i32 kernel assigned identifier for a given peer on the 1-to-many SCTP socket.  ASSOC_ID == SCTP_ALL_ASSOC == 2 might be a secret broadcast address... I haven't tested yet.  If it is one, then it should probably be remapped to fd04:{SITE_ID}::FFFF:FFFF
